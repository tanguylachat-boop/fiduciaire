## Garanties techniques posées

### Multi-mandant first-class
Tous les modules filtrent par `client_id` :
- `bexio_client` : `client_id` obligatoire au constructeur, sync isolée par mandant
- `vendor_account_history` : `lookup` filtré, table à clé composite incluant client_id
- `entry_proposer` : `client_id` paramètre obligatoire, persist en table dédiée
- `plan_comptable_mapper.from_bexio_cache` : filtré par `client_id`

Tests d'isolation explicites : `test_isolation_multi_mandant` dans bexio, vendor_history, entry_proposer.

### Bexio 100% read-only
- Aucune méthode `create_*`, `update_*`, `delete_*`, `post_*`, `put_*`, `patch_*` exposée.
- `__getattr__` sentinel lève `AttributeError("interdite par design")` sur toute tentative.
- Test `test_write_methods_blocked` couvre les 6 préfixes.

### PAT jamais loggé
- Test `test_pat_never_logged_on_error` vérifie via caplog qu'un PAT `VERYSECRETPAT` n'apparaît dans aucun log même en cas d'erreur HTTP 500.
- Stockage prévu : Keychain macOS via `keyring` (à brancher quand le vrai PAT arrive).

### Idempotence
- `init_accounting_schema` : `CREATE TABLE IF NOT EXISTS` pour toutes les tables.
- `sync_to_local_cache` : `INSERT OR REPLACE` upsert, journal des runs séparé.
- Test `test_sync_to_local_cache_idempotent` : 2 syncs successives → 3 rows (pas de dup) + 2 entries dans le journal.
